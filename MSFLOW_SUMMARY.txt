
MSFLOWPOSENET ARCHITECTURE - EXECUTIVE SUMMARY



Total parameters: 4.48M (very lightweight)
  - Decoders: 0.80M (18%)
  - Flow Heads: 2.72M (61%) ← Largest component
  - Context modules: 0.96M (21%)

Single-pass coarse→mid→fine architecture with RAFT-style iterative refinement
at fine level (4 GRU iterations by default).

No learned PoseHead; instead uses geometric Image Jacobian + weighted least 
squares (WLS) to directly solve 6-DOF from 1,610-pixel optical flow field.





1. DECODERS (Shared Q/R features)
   ├─ Coarse ScaleDecoder:      512d → 64d (L2 normalized)
   ├─ Mid ScaleDecoder:         512d → 64d (L2 normalized)  
   └─ Fine FineDualDecoder:     SD 512d + DINO 768d → 64d (fused + normalized)
   
   Output: All scales at 64d (allows shared correlation computation)

2. CORRELATION FUNCTIONS
   ├─ Coarse: Global all-pairs (every pixel vs all 80 render pixels)
   │         Output: (B, 80, 7, 10)
   │         Cost: 1,610 × 80 = 128,800 dot products
   │
   ├─ Mid: Local correlation (9×9 search window, radius=4)
   │        Output: (B, 81, 15, 20)
   │        Cost: 300 × 81 = 24,300 dot products per image
   │
   └─ Fine: Warp-guided local correlation (iterative, 4 refinement steps)
            Output: (B, 81, 35, 46)
            Cost per iter: 1,610 × 81 = 130,410 dot products
            Total: 4 iters = 521,640 dot products

   Implementation: PyTorch unfold (vectorized, ~10× faster than loops)

3. GRU REFINEMENT BLOCKS (Per scale)
   
   Architecture per block:
   ┌─────────────────────────────────────────────┐
   │ Input: corr(80/81ch) + flow(2) + conf(1)    
   │        ↓                                      │
   │ Correlation Encoder: Conv 128d → 64d        │
   │        ↓                                      │
   │ ConvGRU (hidden_dim=128):                    │
   │   z = σ(Conv([h, x]))      [update gate]    │
   │   r = σ(Conv([h, x]))      [reset gate]     │
   │   h̃ = tanh(Conv([r⊙h, x]))  [candidate]     │
   │   h_new = (1-z)⊙h + z⊙h̃                     │
   │        ↓                                      │
   │ Flow Head: 128d → 64d → 3d (du, dv, conf)   │
   │        ↓                                      │
   │ Output: Δflow, new_confidence, new_hidden    │
   └──────────
   
   Optimization: Fused z/r gate (one conv → chunk) saves 2 convs/iter
   Parameters per head: ~0.9M
   
   Fine layer runs 4 times (RAFT-style sequence loss)

4. CONTEXT ADAPTERS (Between scales)
   
   Purpose: Inject scale-specific features into upsampled hidden state
   
   Operation:
     h_upsampled @ prev scale (bilinear interp)
           ↓
     Concat with q_feat @ current scale
           ↓
     Conv3×3 → GroupNorm → GELU → Conv3×3
           ↓
     Residual add: h_new = h_up + adapter_output
   
   Prevents spatial information loss from upsampling

5. MULTI-SCALE FEATURE PYRAMID
   
   Level    │ Resolution │ Use                      │ Pixels  │ Corr Ch
ping github.com
   Coarse   │  7×10      │ Initial global context   │    70   │  80
   Mid      │ 15×20      │ Coarse→Fine handoff      │   300   │  81
   Fine     │ 35×46      │ Final flow + pose solve  │ 1,610   │  81
   
   Upsampling: Bilinear interpolation + flow scaling (critical!)
   When upsampling from coarse to mid:
     flow_mid = interpolate(flow_coarse, size=(15,20))
     flow_mid[:, 0] *= (20/10)  # scale x component
     flow_mid[:, 1] *= (15/7)   # scale y component





Core Equation:
  For each pixel at depth Z, camera motion ξ=[tx,ty,tz,ωx,ωy,z] produces flow:
  
  Δu = fx[-ωx·x·y + ωy(1+x²) - ωz·y + tx/Z - x·tz/Z]
  Δv = fy[-ωx(1+y²) + ωy·x·y + ωz·x + ty/Z - y·tz/Z]
  
  where x=(u-cx)/fx, y=(v-cy)/fy are normalized pixel coordinates
  
  This is LINEAR in ξ! → Can use weighted least squares

Jacobian Matrices: (B, N, 6) where N=1610 pixels
  Ju = [fx/Z, 0, -fx·x/Z, -fx·xy, fx(1+x²), -fx·y]
  Jv = [0, fy/Z, -fy·y/Z, -fy(1+y²), fy·xy, fy·x]

Weighted Least Squares Solve:
  minimize_ξ: Σ w[i] · (||Ju[i]·ξ - flow_u[i]||² + ||Jv[i]·ξ - flow_v[))i]||
  
  Normal equations: (J^T W J) ξ = J^T W flow
    J^T W J = (B, 6, 6)   [Hessian, highly conditioned]
    J^T W flow = (B, 6)   [RHS vector]

Levenberg-Marquardt Damping (Adaptive):
  diag = torch.diagonal(JtWJ)
  diag_damping = damping * diag.clamp(min=1e-6)  # Per-DOF adaptive
  JtWJ_reg = JtWJ + torch.diag_embed(diag_damping)
  
  Advantage: Each DOF damped proportionally to its scale
  Natural robustness to magnitude differences (meters vs radians)

Solution:
  delta_xi = torch.linalg.solve(JtWJ_reg, JtWr)  # (B, 6)
  
  Safety clamps:
    delta_trans = delta_xi[:, :3].clamp(-2.0, 2.0)      # ±2 m/iter
    delta_rot = delta_xi[:, 3:].clamp(-π/2, π/2)        # ±90°/iter

Why Geometry Over Learned PoseHead?
  • 1,610 pixels vs 6 DOF = 268:1 overconstrained (highly stable)
  • Transparent: Can inspect which regions drive the solution
  • Confidence weighting: Naturally handles occlusions/uncertainty
  • No learned bias: Pure geometric signal
  • Invertibility: 6×6 linear system, numerically stable

 COMPUTE ANALYSIS


Forward Pass Breakdown (Per-iteration priorities):

1. Local Correlation (~40% of compute)
   Fine layer: 1610×81 = 130,410 multiply-adds per iter
   4 iters: 521,640 MACs
   Implementation: unfold + pointwise multiply + sum (GPU-efficient)

2. ConvGRU Gates (~30%)
   Conv3×3 with 128 input channels
   3 convolutions per step × 4 iters = 12 convolutions
   Each conv: 12864×3×3 at 1610 spatial locations

3. Warp-Guided Interpolation (~15%)
   F.grid_sample() × 4 iterations
   4-sample bilinear interpolation per pixel × 1610 pixels

4. Geometry Solver (~5%, serializes on Jacobian)
   Jacobian computation: O(N) = O(1610)
   6×6 linear solve: O(1) basically (tiny)
   Not on critical path

Critical Insight: FINE LEVEL DOMINATES (4 iterations)
  Coarse one pass: ~5-10% of total compute
  Mid one pass:    ~5% of total compute
  Fine 4 passes:   ~80% of total compute

Phase 1 (Warmup, 8 epochs):
  Loss: flow_loss only (no pose loss)
  Purpose: Train FlowHead to produce reasonable pixel matches
  Gamma: 0.95 (early fine iters weighted more)

Phase 2 (Joint, 112 epochs):
  Loss: flow_loss + pose_weight * pose_loss + conf_reg_loss
  pose_weight: Gradually ramps from 0.1 → 1.0 over 8 epochs
  Purpose: Once flow is reasonable, gradient through geometry solver
  
Loss Components:
  1. Multiscale flow loss (RAFT sequence loss for fine)
     Weights: coarse(0.1) < mid(0.3) < fine(1.0)
     Sequence loss: γ^(N-1-i) per iteration i of N fine iters
     γ=0.95: Emphasizes final iteration (less noise from early iters)
  
  2. Confidence regularization
     Prevents collapse to all-zero or all-one confidence
     Calibration: High confidence → low flow error
  
  3. Pose loss (rotation + translation)
     Rotation: cosine loss (1 - cos θ) ← smooth gradient
     Translation: L2 loss
     Weights: trans 10× rotation (translation typically harder)

Data Augmentation:
  ✓ Additive noise on pose (constant 8°, 0.25m)
  ✓ Re-rendering (5 outer iterations per training step)
  ✓ No curriculum (constant noise better than ramping)

 KEY TAKEAWAYS FOR OPTIMIZATION


Memory Bottleneck:
  1. Fine GRU hidden state (805 KB/sample, cannot reduce without retraining)
  2. Fine correlation (509 KB/sample, essential for refinement)
  3. Coarse global correlation (440 KB/sample, computed once)

Compute Bottleneck:
  Fine level with 4 GRU iterations consumes 80% of forward compute
  → fine_iters is main knob for speed/accuracy trade-off

Current Design is Near-Pareto Optimal:
  • Every major component justified by empirical results
  • Doubling decode_dim doesn't help (already sufficient)
  • hidden_dim=128 is empirically tuned sweet spot
  • Fine resolution (35×46) is limited by DINO patch grid

To Break Accuracy Floor (0.81°):
 Increase fine_hw to 60×80 (exp050) — proven to work
  → Requires reducing batch_size 4→2
  → Requires additional compute budget

Low-hanging Fruit:
  1. Try fine_iters=8 (was 4) — +0.3-0.5° accuracy, fast to test
  2. Try outer_iters=5 (was 3) — +0.3° accuracy, slow but proven
  3. Try gamma=0.95 (was 0.8) — +0.1° accuracy, no cost

Recommended Next Steps for Your Use Case:
  1. Profiling: Run on your dataset with fine_iters={4,6,8}, measure speed/accuracy
  2. Memory: Check max GPU utilization; if <80%, increase batch_size or fine_iters
  3. Accuracy: If >0.81° error, try exp050's recipe (60×80 fine_hw)
  4. Speed: If constrained, reduce outer_iters 5→2 (biggest impact)
