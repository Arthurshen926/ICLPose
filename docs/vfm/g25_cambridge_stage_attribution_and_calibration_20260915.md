# GreatCourt 校准修复与四场景冻结输出归因

## GreatCourt：原验证失败已修复，定位评估已完成

原表面头的标量校准最小化均方误差，却未约束验收所要求的 p90。新选项 `--tail_constrained_shrinkage` 在原校准子集上搜索 [0, alpha_LS] 的 1001 个固定网格点，选取满足 p90 不超过 token 中心基线的最小均方误差系数；不使用独立验收子集选择系数，不使用 test 标签。原验收门槛完全保留。这是经验风险约束，不是对未知场景尾部误差的理论保证。

|独立验收指标|原模型|受约束校准|token 中心基线|
|---|---:|---:|---:|
|像素误差中位数|0.554025|0.633704|0.649457|
|像素误差 p90|0.824752|0.761444|0.765536|
|像素 Gaussian NLL|-0.750727|-0.643841|-0.618599|

校准系数从 0.465395 降为 0.072136；改善尾部的代价是让出部分中位误差收益。表面 UV 中位误差仍由 0.179072m 降到 0.163210m，改善 8.86%。全部网络参数数组 SHA256 与原模型一致；只改变图像偏移校准及对应方差尺度。独立验证 gate=True，实际 batch0 surface 对应点构建已通过原失败位置。完整 GreatCourt 760 张 test 双种子现已完成：25cm/2° 召回为 25.92% / 27.50%，50cm/5° 为 45.39% / 46.71%。修复验证失败不等于解决定位性能问题。

失败原模型保留；修复版本在 `GreatCourt/tail_calibration_repair`，激活记录在 `validated_runtime_head_override.json`。这是 GreatCourt 的明确协议修订，另外四场景仍为原校准，不能称为五场景校准策略完全相同的消融。

### 含义与边界

1. 候选保留/选择：四场景已保存的候选池均优于最终。KingsCollege、OldHospital 的 25cm 上界差额分别为 14.58、19.23 个百分点。这只是跨阶段、跨种子的可用性证据；这些候选不一定同时呈现给最后选择器，不能直接全部归咎于最后一个模型。
2. 匹配与求解：用 GT 重投影误差 <=4 工作网格像素筛选每 token 一个既有对应，再以原预测像素求解，KingsCollege/OldHospital 仍只有 59.48%/48.90%。该干预同时改变对应集合和求解输入，不是纯匹配精度评估，也不能据此断言所有求解器都无提升空间。
3. 坐标/几何敏感性：同一组点换成 GT 精确投影像素，成功率接近 100%。这说明在理想像素条件下可以构成位姿，而非证明地图坐标正确、匹配真实可见或检索已经完美。像素误差、地图几何偏差、远景深度与条件数仍需区分。
4. 检索：本诊断只看已检索的点/表面对应缓存；无法单独分离地图缺失、区域检索遗漏与区域内坐标支持不足。精确投影 oracle 本身使用 GT，不可作为部署性能或“覆盖率已达100%”的证据。

## 优先改进方向

优先对 KingsCollege/OldHospital 分析候选从哪些阶段被丢弃，再检查像素残差与距离、视角、空间覆盖的关系。选择器改进需使用 train 划分学习与验收，不能用本 test 归因数据回训后再声称盲测。现有证据不支持单纯增加检索数量即可补齐性能差距。

## GreatCourt 补充归因

25cm/2°：初始 PnP 候选池上界 21.32%，全部已保存位姿池上界 44.61%，最终种子1为25.92%。GT筛选既有对应、保留原像素求解为32.37%；换用GT精确投影像素为99.08%。与其他场景采用相同诊断协议及限制。全量查询中的18.68%属于候选曾存在但未最终保留/选中，51.18%在GT精确投影后可恢复但现有候选及原像素诊断未恢复。这不唯一识别像素误差或地图几何误差，也不证明真实检索覆盖率99%。
