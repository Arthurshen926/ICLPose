# 候选条件化匹配器与定位 LoD：实现、实验和未解决问题

日期：2026-09-13。依据本轮附件 `9c0d3f26-5597-46d8-bc2d-3b0bbbcd56aa/pasted-text.txt`。结果根目录：`output/g25_pose_transport/planar_map_rendered_ransac_v1/surface_coordinate_upgrade_v1/overlap_lod_v402`，下文简称 R。

## 结论与采用决定

本轮完成了真正训练的候选条件化 overlap/identity 匹配器、保留原始几何的三级定位 LoD，以及平铺/LoD × MNN/学习匹配器的完整对照。不是仅修改损失名称或画概念图。但尚未获得超过现有强基线的全面定位提升，塔尖遮挡案例也仍未解决。保留 v357 强基线，不自动替换默认方法。

LoD＋MNN 在两种 RANSAC 种子下，经过相同精修后的 50 cm 召回均高于平铺 MNN；学习 overlap 有中间监督收益，identity 与最终位姿则仍落后。LoD 大幅减少描述子比较量，但同等优化程度的算子计时尚不支持加速结论。应继续这条方法路线，但不能据此宣称鲁棒性突破、理论完备或投稿证据齐备。

## 1. 从可视化到可检验的任务定义

MoGe 提供相机坐标下的表面与可靠性，不等于该表面存在于候选地图。RADIO 外观相似也不等于物理位置一致。需要分开建模：

\[
p(o_i,z_i\mid Q,M_c)=p(o_i\mid Q,M_c)\,p(z_i\mid o_i=1,Q,M_c),
\]

其中 o 是查询与候选区域是否具有共有可见支撑，z 是条件物理锚点身份。之后才利用原始锚点和细网格坐标求解位姿。该因子分解明确任务，但本身不保证预测校准、可识别性或位姿成功。

旧方法的问题不只在前景权重：存在候选截断、视图模式折叠、null/独立 argmax、互近邻约束以及几何关系传播的连续流失；小范围正确支撑也可能几何退化。人能识别“这是塔尖”，不代表能准确判断塔尖上每个像素对应哪个三维点，更不代表只靠它能达到厘米级平移精度。

## 2. 已实现的专用匹配器

实现：`feature_extract/tools/vfm/partial_overlap_matcher.py`，训练与数据构建分别为 `train_partial_overlap_matcher.py`、`prepare_overlap_lod_training.py`。

- 冻结 RADIO 粗/细特征、MoGe、地图坐标与原精修器。80,132 参数的查询上下文注意力、候选稀疏交叉注意力、overlap 头及条件 identity 残差头。
- 每个区域保留每个查询 token 的原始 top16 外观模式，不先平均坐标或折叠为四个 texel。identity 用离散模式，不回归三维均值。
- 上下文注意力保留全局外观信息；metric 消息只在查询局部邻域、可靠深度且深度比兼容时传播，再乘两端 overlap 概率。不从污染的 top1 对应估计世界/查询尺度。
- 身份正样本采用可见且投影/深度相容的集合，优化集合边缘概率；遮挡、缺失和边界歧义设为 unknown，忽略其监督梯度。数据中的可见性仍是共享重建的渲染代理，并非独立物理身份真值。
- 训练使用实际 flat/LoD 检索区域并排除同 mapping route；提案先冻结再读取监督。矩形特征删除的目标忽略，不把被删除内容当可见正样本。
- 140 mapping queries、1012 区域对：seq1/2/4/6 训练 591 对；seq7/8/11 共 421 对。固定 12 epochs；仅 seq7 标定 overlap 温度与偏置。seq8/11 未参与本头训练或标定，但共享场景、几何及既有特征，因此只是头级保留验证。
- 四组共同使用 3×3 细特征网格坐标搜索。没有训练 subtoken 坐标头，旧字段已修正为 `subtoken_head_used=False`，另设 `fine_grid_search_used`，避免把搜索称为训练能力。

正式结果使用 `training_covariance_fixed` 与 `model_covariance_fixed`。第一版误读可选协方差字段导致输入全零；已改成强制读取 `prototype_world_covariance_m2`、检查形状和有限值，修复冻结数据的协方差通道，重新训练并完整重跑四组。R 下无 `fixed` 的早期实验是调试结果，不纳入本文性能结论。

保留验证结果（校准 overlap 阈值 0.5）：

|路线|overlap 精确率|overlap 召回率|identity top1|原 coarse top1|
|---|---:|---:|---:|---:|
|seq8|80.75%|72.26%|41.42%|42.30%|
|seq11|75.47%|71.73%|35.45%|40.22%|

因此不能把 overlap 学习有效等同于匹配器整体有效。映射集诊断中，用 overlap 过滤 MNN 可提高严格投影/深度正代理比例；完整学习解码器没有保持这一优势，还引入约 2–3% 重复锚点。其保留 top2 身份、缺少全局互斥解码，以及大量未标注的隐藏候选，都值得后续独立消融。这是诊断线索，尚不是单因素因果证明；本轮未追加 overlap-only 的全量位姿实验。

## 3. 定位 LoD 的实现及理论边界

实现：`localization_lod_memory.py`。L0 为 8 m 父块多外观代表；L1 为 2 m 子块多外观代表；L2 为原始 91,976 个锚点身份及不可变度量坐标。752 个粗代表、2818 个细代表；索引数组约 1.54 MB，不包含完整特征库和几何。

每个查询 token 先开两个父块、父块内两个子块，另通过全局 L1 局部代表打开一个旁路子块，防止小型独特区域被粗尺度摘要否决。打开叶后才读其原始锚点；四个区域提案使用相同代表库统计量、外观密度补偿和空间覆盖规则。初始展开不需要相机位置，也不用 GT。

这是现有地图上的定位索引与动态展开，尚不是学习区域边界/成员，更不是重建端完成了多层几何。L0/L1 尺度仍固定。最终 PnP 坐标来自 L2 原始锚点，不能把不同表面的均值当可测量点。

全局局部旁路仍扫描 L1，因此不能声称 O(log N)；当前是压缩代表库扫描加叶内精确读出。实测平均描述子比较量从 24.27 M 降至 1.74 M（约 −92.84%），叶锚点读数约 −99.57%。计数不是内存流量或端到端速度。

独立的 20 个 mapping seq7 查询、交替执行顺序、三次重复中位数算子基准，去掉平铺检索无用统计后：平铺约 70.25 ms、LoD 81.93 ms。两者精确 atlas 行 top1 一致率 57.77%，不等于物理身份召回。当前 Python 逐 token 排序/展开开销抵消算术节省；没有外存流式加载或原始 RGB→位姿端到端测速，不能宣传大场景速度优势已被证实。

已有 [LoD-Loc](https://arxiv.org/abs/2410.12269) 使用建筑 LoD 地图进行空中定位，因此不能宣称首次 LoD 定位。[Octree-GS](https://city-super.github.io/octree-gs/) 的渲染细节选择可作启发，但定位展开应依据检索证据及位姿信息，而不只依赖已知相机距离。[PREDATOR](https://overlappredator.github.io/) 提供低重叠条件化思路；[LightGlue](https://arxiv.org/abs/2306.13643) 和 [RoMa](https://arxiv.org/abs/2305.15404) 分别支持自适应匹配计算和粗细匹配设计的相关背景。这里的 image-to-map 适配及有效性必须由自己的实验建立。

## 4. 完整定位实验

438 查询，seq10/seq13；五个计算分片不是五个独立场景。所有方法使用同一地图、查询、四区域预算、256 measurement tokens、16 身份候选上限、每区域最多 250 RANSAC 假设、同一精修及读出器。solver 权重随匹配策略变化，学习分支 overlap×identity，MNN 为单位权重；因此四组验证的是整个匹配策略，不能隔离单独网络架构收益。细坐标先计算，原始候选选优在共同细坐标假设上评分。

首种子，相同精修后（未接强基线）：

|方法|平移均值/中位数 m|旋转均值/中位数 °|10 cm/1°|25 cm/2°|50 cm/5°|
|---|---:|---:|---:|---:|---:|
|平铺＋MNN|0.782 / 0.145|2.533 / 0.452|31.51%|76.48%|88.36%|
|LoD＋MNN|∞ / 0.144|∞ / 0.456|29.91%|77.85%|89.73%|
|平铺＋学习|∞ / 0.186|∞ / 0.618|18.04%|61.87%|80.59%|
|LoD＋学习|∞ / 0.181|∞ / 0.636|21.00%|62.79%|80.82%|

无效位姿作为失败保留，故均值为 ∞，没有只对成功图像求均值。次种子 MNN 精修后：平铺 25/50 cm 为 75.80/90.41%，LoD 为 77.63/91.32%。两个种子支持该阶段小幅收益，不能证明统计显著性；原始前端首种子的 50 cm 增益 2.97 个百分点，次种子仅 0.23 个百分点，1 m 优势未复现。

对现有强基线，另做固定次级读出：只接受已通过原验证器、且相对基线平移超过 0.5 m 或旋转超过 3° 的新模式，否则保留基线细精度。阈值来自已有模式分离规则；这是读出对照，不是新校准的低重叠验证器。

|最终输出|平移均值/中位数 m|旋转均值/中位数 °|10 cm/1°|25 cm/2°|50 cm/5°|
|---|---:|---:|---:|---:|---:|
|原强基线|0.697 / 0.108|1.820 / 0.347|47.26%|89.73%|95.43%|
|LoD＋MNN，模式读出，种子1|0.511 / 0.108|1.568 / 0.349|47.26%|89.04%|94.52%|
|LoD＋MNN，模式读出，种子2|0.622 / 0.108|1.976 / 0.350|47.03%|88.58%|94.52%|

种子1平移均值降低很大程度来自 frame00136 的 80.81 m→3.19 m，不能把尾部修复说成 25/50 cm 成功率提升。严格召回仍退步，所以不推广为默认输出。塔尖 frame00142 的新 LoD 分支未给出有效位姿，最终回退仍为原来的 17.25 m/116.97°。

R/metrics_table.md 和 summary.json 包含全部均值、中位数、召回率和无效率。24 个输出组、120 个位姿文件包括阶段、读出和重复种子，不是 24 项独立方法实验。completion_audit.json 记录文件哈希、查询集合一致性、有效旋转检查和回退逐位一致性。

## 5. 塔尖诊断的新结论

R/diagnostics_equal_count 为权威诊断。手工塔尖轮廓和查询 GT 仅用于事后解释，不参与训练、检索或选参。“正确候选”定义为投影误差≤4 coarse pixels 且查询深度相容的代理，并非独立物理身份真值。

19 个旧前端采样塔尖 token 中，地图存在位置相容代理的有 10 个；区域保留 10、top32 保留 9、不同 texel top4 保留 6、独立 null/argmax 剩 2、MNN 剩 1、joint 剩 0。原始 top16 仍可保留 9，说明过早折叠身份模式确实可能伤害支撑。

纠正先前解释：正确位置代理的全图排名中位数是 76，不是 2；“任意塔尖区域锚点”的高排名不能证明“该像素的正确物理锚点”已排到最前。缺失代理的 token 不能直接算错误匹配或不可匹配，因为渲染监督也有不确定性。

理想 GT 投影对应的等数量实验，每档 20 个噪声种子：

|理想支撑|点数|0.25 coarse px 噪声的平移中位数|0.5 px 噪声的平移中位数|归一化 Jacobian 条件数|
|---|---:|---:|---:|---:|
|塔尖集中区域|14|0.675 m|1.343 m|47.14|
|全可见范围分散取样|14|0.016 m|0.032 m|12.97|
|全可见范围|179|0.005 m|0.011 m|12.17|

这是一项共享地图上的合成噪声敏感性诊断，既非真实可达精度上界，也非新模型定位成绩。它支持“空间分布、视差与几何条件不能被语义独特性替代”。现精修仍要求至少 32 支撑，接受规则还保留至少 24 支撑；它们也不适配只有少量可信对应的情形。不能仅把门槛降到 14，需要同时量化解的条件性和证据置信度。

## 6. 尚未完成的附件建议与下一步优先级

1. **身份学习及未知监督**：先固定 MNN 解码，验证单独 overlap 过滤是否产生全量最终收益，再独立加入候选集合解码。需要更可靠的跨视图物理身份/可见性监督和真正重复结构 hard negatives，避免 unknown 被当作可任意竞争的隐性负例。当前学习器的失败不证明专用匹配器没有价值。
2. **少量但充分的支撑验证**：在 mapping 保留集上学习/标定接受概率，区分“没有证据”与“出现矛盾”；结合重投影、覆盖范围、深度分布、位姿条件性和跨候选证据。不能用测试 GT 决定采用哪条分支。现模式读出未解决此问题。
3. **坐标不确定性与可观测性**：本轮未训练细坐标/协方差头，也未把 Fisher/Jacobian 信息增益接入 token/区域选择。应在共享区域与身份先可靠后，学习坐标噪声并选择互补地标，避免只放大集中塔尖支撑。
4. **学习 LoD 展开和地图集合价值**：当前固定 8/2 m 索引仅是可运行起点。可学习部分应优先针对在计算预算下增加正确模式与位姿约束的展开价值，再考虑成员/边界；保留度量锚点身份及局部旁路。尚无重建端 LoD、可学习边界成员、外存流式加载或大规模扩展实验。
5. **投稿级验证**：还需要该新分支的独立场景、固定开发/确认协议、自然低重叠/遮挡/重复纹理分层、地图规模与端到端成本、监督代理误差检查，以及专门的模块消融。项目此前的其他跨场景结果不能替代这些新模块的验证。当前没有支撑 25 cm 召回达到 90% 以上的新证据。
