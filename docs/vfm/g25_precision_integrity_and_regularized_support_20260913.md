# 10cm召回完整复核与支持扩展：v355–v358

## 结论

可独立复核的10cm/1°变化链是29.2237% → 44.2922% → 45.8904% → 46.8037%。主要跃升发生在v327到v340引入连续特征对齐时，不是上一轮突然从20多涨到46%。本轮新增v357普通损失、带运动正则、全部合格支持点配置进一步达到47.2603%，25cm/2°为89.7260%、50cm/5°为95.4338%。全部门限来自同一配置，90%目标仍未达到。

本轮未发现导致虚高结果的指标计算、查询错配或新增精修链路读取query标签问题。不能将这些检查表述为“整个项目已被证明绝无bug”。当前数据仍是两条反复用于开发的路线，未提供独立新场景泛化证据。

## 独立复核

1. 不调用旧误差或指标函数，直接求逆w2c矩阵得到相机中心，使用SO(3)旋转对数计算角误差。对v327、v340、v344、v353和新v357全部438张逐查询重算，所有召回与原报告一致，误差数值差约1e-13。检查位姿有限、齐次末行、旋转正交和正行列式。
2. 每组均为同样438个唯一查询，姓名顺序一致；真值文件metadata中的image_id与查询名逐一吻合。未删除失败或只在accepted子集上计算。10cm门限始终同时要求平移≤0.1m且旋转≤1°。平移计算相机中心差，不是w2c平移向量差。
3. 建图lineage来源与query名无交集；投影器metadata中的训练路线为seq1/11/2/4/6/7/8，验证路线seq9，无seq10/13。读取到的query特征缓存声明poses_or_labels_opened=false，并绑定原投影与checkpoint。metadata检查不能代替从原图、训练脚本开始的完整上游重建。
4. 运行时通过Python审计钩子禁止打开查询contributor标签文件及metrics.json，并先用禁止读探针验证守卫生效。从已冻结v327出发，对438张重跑多分辨率阶段和细精修阶段；两阶段位姿均与原输出逐元素完全一致，没有任何非探针的禁止读尝试。来源与实际打开的数据文件列表全部保存。这个复核覆盖新增连续精修链路及其固定输入，**没有从原始RGB重跑v327上游，也不是对所有第三方原生I/O的通用沙箱证明**。
5. 保持原初始化、地图和几何支持，固定随机种子打乱查询特征的空间位置，重跑438张第二阶段作为负对照。10cm/25cm/50cm变为15.9817%/65.9817%/91.5525%，平移中位数0.194347m。它证明本设置的收益依赖空间特征信息；不能据此证明所有数据来源均无泄漏。该控制仅用于诊断，不是候选方案。

29.22%到46.80%的变化与平移中位数从0.141030m下降到0.107783m一致：严格门限附近样本跨过10cm会造成较大的召回变化。原方法与连续精修使用的实际特征支持、连续求解和计算预算不同，因此不能把累计收益全部归因于一个小模块，也不能声称等成本提升。

## 本轮优化

共同初值为v344多分辨率鲁棒预测，第二阶段固定支持后优化细特征残差，运动正则lambda=0.02，继续施加阶段内0.5m、3°、4像素约束。新增三组：鲁棒512、鲁棒全部、普通全部。原v353普通512作为对照。全部模式只扩大到实际可用的唯一token支持，并非保证每张都有2304个点。普通损失与鲁棒损失的有效相对正则强度不同，因此不能单独以结果宣称某一种噪声模型更真实。

## 理论和未解决问题

扩大支持降低硬性512截断的信息损失，但不新增物理身份信息；共享特征主干、相邻token上下文重叠使这些支持不能视为独立同分布观测。局部运动惩罚只约束离开初值的幅度，不是额外传感证据。目标改善与优化器成功不等于定位可信：空间打乱控制也有大量优化接受，但实际位姿退化，直接说明当前接受规则不是校准的正确性验证器。

主要剩余缺口仍是错误物理位置消歧、可靠的候选接受/拒绝及新场景验证。没有由本轮解决几十米级错误，也没有完成附件全部建议。对这一批开发数据继续调参可带来收益，但必须冻结配置后做独立路线/场景与强基线比较，才能支撑论文的鲁棒性主张。
