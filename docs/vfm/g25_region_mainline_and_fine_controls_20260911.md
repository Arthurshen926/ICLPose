# 物理区域接入完整主线与精细读出控制（2026-09-11）

本轮把固定物理区域接入了完整 438 查询的历史坐标输入和稀疏/稠密共识后端。相对正确性修复基线，五档召回率均小幅提高，同一有效查询集合的平均平移/旋转误差下降；相对既有 guarded LM 对照，则表现为较宽阈值召回和平均误差更好、严格精度及中位数不占优。开发查询精细读出/稳健精修也有小幅指标收益，但还不足以证明稳定突破。

## 1. 主线到底接入了什么

使用各 split 原 primary 坐标分支的精确冻结对应，保留世界坐标、查询像素、内参和对应人口。把原 PnP 中按物理平面形成的局部种子组替换为预先固定的 6m 物理区域组；区域按去重查询 token 支持度排序，不跨平面比较未经校准的匹配概率。保留 all、atlas/source、query-region 组；区域不足时用原平面组补足，组数与原平面种子组相同。

区域中心来自上一轮固定地图的 regions.npz，未用正式查询位姿生成区域。世界坐标不被区域中心替代，区域可以跨平面、部分可见。五个 split 的非平面初始候选逐一验证，位姿与原基线完全一致。

随后完整重跑 primary 的 view geometry、MoGe、uncertainty，并与不变的原 alternate 分支重跑 sparse geometry、sparse-first render plan、双分支 dense render、原 AND consensus。此次只改变 primary 分支的种子组织，不是同时修改两个分支。

主线用原 OpenCV RANSAC 参数（每调用最多 1000 次迭代，自适应停止），所以“等预算”准确指相同种子组调用数和相同参数上限，不是实际评分假设数或墙钟时间完全相同；不能套用前几轮 224 查询固定 256 假设/组的说法。

## 3. 保留原假设再增广区域的对照

在 seq10 和 seq13 shard0 上，保留全部原平面候选，再加入区域候选，重跑相同完整后端。验证原有候选逐个保留且位姿完全一致。seq10 最终位姿与区域替换完全相同；shard0 召回率和中位数相同，但有少量位姿变化，其中一个大误差结果略变差。因此增广没有改善这两组主要指标，不能说所有最终位姿完全相同。

这个结果不能证明所有失败都来自后端选择，但保留旧候选也未恢复原基线表现，因此“仅仅因为旧候选被删掉”不足以解释这两组结果。后端对新增区域候选的选择和后续精修需要单独研究。增广增加种子组调用，不是等计算对照；未扩展到其余 split，也没有把它当作完整 438 增广结果。

## 5. 对区域记忆和未完成建议的判断

物理区域方向已经有两种层级的正面证据：弱候选后端上显著减少大误差，完整强主线上小幅改善较宽阈值召回。收益大小依赖输入与后端，不能把 224 查询上的幅度外推到主线。地图组织确实影响现有信息的利用，但这仍是固定区域边界的证据。

可学习区域成员/边界、集合边际效用、跨路线区域监督、区域整体前端召回仍未实现，旧学习器的负面结果也未被本轮洗掉。本轮没有新增学习器，不能把固定区域收益包装为可学习地图已经获胜。高分辨率/RADIO/MoGe 能力同样没有被证明耗尽。

下一步优先检验区域候选的选择与精修一致性，以及区域与 guarded LM 的组合；学习部分应先匹配部署目标和多路线监督。单纯增加候选或增加像素分辨率并不保证改进。当前不扩大地图，不引入新 backbone，不自动改写默认主线配置。
