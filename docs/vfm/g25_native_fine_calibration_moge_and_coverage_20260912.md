# 原生细读出继续推进：校准、MoGe局部聚合、相关误差与精测覆盖（2026-09-12）

本轮新增8种配置，每种在同一438查询上完成最终不确定度精修、原稀疏验证、重新生成的主备稠密渲染及最终共识选择。固定8区域原生前端、世界锚点、候选身份库存与备用分支；各组使用其基线已冻结的MoGe初值，token组合与原token-AP3P对照，其余与wide对照；没有按GT为不同查询选择配置。

中位数与召回包含438查询。表中平均误差*采用前轮固定436个公共有效查询；全量均值与无效率另列。5个分片来自两个反复开发的路线，不是5个场景；本轮建图留出路线只确认测量模型，不等于新场景定位确认。

**已确认的主线结论：** 小块独立细读出经过幅度及方差校准后，严格召回28.54%→29.45%，平移中位14.52cm→14.24cm。扩大实际精测覆盖后，25cm召回81.51%→82.65%、50cm召回94.52%→94.98%、平移中位14.52cm→14.21cm；条件平均平移下降约4.76mm、旋转下降约0.01567°。但扩大覆盖使10cm召回略降，不能将不同配置的收益拼成一个方法。

**明确的负向/混合结论：** MoGe硬表面读取没有整体胜过原细读出；共同对齐时50cm召回较好，但10cm与25cm退步。加入rho约0.03的相关协方差，相对同坐标同方差的独立联合校准，均值与中位点估计略差，严格召回下降、25cm召回略升，尚无整体收益。它完成了相关误差的理论和实现对照，但当前不是优先性能开关。

**组合验证：** token-AP3P＋校准细读出相对原token分支，10cm召回29.6804%→30.1370%，25cm保持81.9635%，50cm从94.0639%降至93.8356%。平移中位14.3138cm→14.2101cm，旋转中位0.49740°→0.49495°。全438查询均为有限输出，平均平移0.761358m→0.760307m、平均旋转1.985144°→1.982026°。新增细读出的严格召回贡献仅为0.4566个百分点；相对wide的更大差异包含以前token初始化已有的贡献。严格召回差的块长10区间[-0.6849,+1.5982]个百分点，仍不能称稳定提升。

## 2. 建图路线监督与校准合同

复用精确91,976原型的匿名细读出。对每个建图目标视图，仅允许来源于其他建图路线的原型；用固定米制锚点投影和2DGS深度检查生成条件坐标教师。深度容差固定为max(0.10m, 1%深度)，每token保留粗描述相似度最高的可见身份、每图最多128条。训练路线seq1/2/4/6各20图，留出seq7/8/9/11各20图。它是“给定近似正确身份后坐标是否更准确”的监督，不模拟全部原生召回错误，也不把地图投影叫作人工材料点对应真值。

所有系数只在训练路线拟合，留出路线不参与选择或拟合；查询seq10/13的GT没有进入校准。地图本身仍由既有全部建图路线构造，因此留出不是整个系统的建图数据留出。

独立读出幅度alpha=0.353501，方差倍率=1.246304。alpha由按图均衡的受限最小二乘拟合并限制[0,1]，避免越过已有token；方差倍率按二维高斯残差拟合。只改变实际精测行，其他行沿用原坐标与方差。

## 3. MoGe进入匹配前的局部聚合

使用既有query平面标签，在双线性特征读取时排除落在其他表面或未标记像素上的特征中心，并要求候选位置位于同一已观测表面。没有中心支撑时保持原坐标，没有新增隐藏像素或删除原对应。地图特征、冻结backbone与原MoGe求姿后端不变；独立和共同对齐分别作对照。

原小块掩码仍为平均20.76个token/图；其中约91.64%的中心有同表面支撑。这只改变读出阶段的聚合，不能消除已经混入backbone token内部的跨边界信息，地图端也未重新作MoGe聚合。因此不是完整几何感知特征编码器。

## 4. 共同对齐的相关协方差

在同一批建图教师上，按物理平面和8×8粗token图像块构组（至少3个）。共同读出的幅度alpha=0.185197、方差倍率=1.354794；按图均衡的残差成对矩估计rho=0.029972，限制[0,.95]。建图分组没有query MoGe细分，是明确的分布差异。

标准化残差的块内协方差为 C=(1-rho)I+rho·11ᵀ。精确分解共同均值方向与组内差异方向进行白化；独立行、单元素组保持不变。一个token的多个身份不能进入同组重复计票，组不能跨query或物理平面。保留原Huber鲁棒损失、位姿步长限制和原支持率接受规则；这是有相关性的鲁棒伪似然精修，不是声称完整后验已校准。

留出路线独立NLL/token=2.982436，相关模型=2.980714，差异较小。joint_calibrated与joint_correlated使用完全相同的坐标、方差和对应文件，只切换块内协方差。

## 5. 解除独立细匹配不需要的小块门槛

原128预算在至少3-token块过滤后，实际平均只剩20.76个。fine_calibrated128移除这项仅服务于共同对齐的限制，仍在冻结初值下选择正深度、4px内、地图细特征可用的每token一个身份，按token顺序均匀取最多128个。实际平均120.90个，中位128个，查询覆盖99.77%。

原小块内的校准像素和方差逐数组保持一致，仅扩大精测覆盖。虽然配置上限均为128，实际参与读出的token和计算量增加，不能说是完全同实际预算对照。所有配置复用先前提取的真实高分辨率RGB特征；本轮构建耗时不包含先前编码，完整部署成本仍需计入这一项。

在前四组完成后，另补token-AP3P＋校准细读出组合：只使用已冻结的alpha和方差倍率、原至少3-token小块掩码，将初值切到此前token分支自己的MoGe终点。不重新抽样、不重拟合参数。该组合属于开发集上的追加探索，与原token分支作直接对照；不能把来自token初始化的已有收益再归因给细读出。

## 7. 正确性、成本与剩余工作

35项相关测试通过，包括同表面插值、映射监督幅度约束、相关白化与稠密矩阵等价、重复token拒绝、侧文件绑定、校准来源拒绝及原位姿精修/共识。新代码通过编译与git diff --check。首次回放预检发现浮点精度变化会在极小相似度差处改变离散选择，已恢复原float32评分并在全部查询上精确回放原fine/joint像素；预检失败产物隔离，未用于求姿。另对全部20,409条建图校准观测检查评分精度转换，离散更新完全一致；校准代码随后统一为与推理相同的float32评分。

另有不读取GT的求解输入审计：固定的是候选身份库存和地图锚点；原精修器仍按初始重投影选择每token解释，更新像素可能改变实际选中的行，并非硬锁全部优化行。独立校准的小块组在公共token中约0.0722%发生身份切换，扩大128预算后约0.4380%；真正使用了更新像素的优化行比例约从3.96%提高到23.32%。完整分母与结果见hypothesis_audit.json。

本轮不增加地图原型或backbone。特征读取阶段的I/O计时保存在mask_cost_summary.json，但group构建一次生成4种配置，full构建仅生成1种，二者不能直接解释为单配置耗时比较。完整RGB到pose的p50/p95和峰值显存账仍未补齐。

本轮没有实现完整学习区域配置匹配器、严格同新增数量的旧过滤归因、原生多建图路线的下一块区域价值学习，也没有新确认场景。MoGe引导聚合及相关误差已经有实际实现和完整位姿对照，但它们的当前简化形式不代表这些方向的上限。

下一步优先级：将统一幅度系数细化为建图监督下的测量可靠性条件模型，结合ROI/精测预算选择；保留独立确认集验证，随后补区域内部配置匹配和原生下一块区域价值。当前MoGe硬边界聚合及统一rho不是优先升级项。

默认配置未自动更改，不合并不同配置的最佳指标。所有实验固定产物与逐查询误差保留在v267–v273目录。
