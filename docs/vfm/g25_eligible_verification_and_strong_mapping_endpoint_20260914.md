# v413：候选资格与排序分离、完整 mapping 强端点

## 结论

完成两种验证决策改进的 438-query、两种子对照，以及七条 mapping 路线到 v357 的完整实际重放。先判定候选资格再排序修复了可复现的决策缺口；生成匹配与保留验证 token 的双证据救援能恢复被错误参考位姿挡住的正确候选。收益主要仍在尾部，10cm 召回未提升，不能称为大幅突破。保留 v411 默认端点，v413 输出作为独立实验分支，不自动升级。

## 决策规则与公平性

原流程先取相对模型的最高分候选，然后检查位姿间隔与 bank 确认；最高分候选不合格就保持参考位姿。这没有求解“合格候选中的最大分数”。新 eligible 规则先要求候选与参考位姿满足已有 0.5m/3° 分离、达到冻结概率阈值、并通过已有 corroborate bank 验证，再从合格者取最高相对分数；没有合格者才保持参考位姿。

dual_support 在没有 eligible 候选时启用单独的实验救援：候选仍须分离，生成匹配与 bank 两个 token 域各至少六个几何内点，且其 unique-token 得分分别严格胜过参考位姿；从合格者按生成域得分排名。得分使用既有词典序“唯一 token 内点数、负截断重投影误差”。bank 用作资格条件，不以其分数选择最大者。

这两个域共享地图、编码器，bank 也曾被早期决策使用，不能声称统计独立或风险已校准。对更多候选应用门控改变了选择过程，旧相对模型的校准不能自动转化为新流程的 95% 保证。没有读取 query 标签拟合模型或调数值门槛，但方案仍是在长期开发队列上探索。

使用 v412 未额外 LM 的分数保留候选、原 v402 候选及同种子 v411 confirmed 参考位姿；没有新增对应或 PnP 假设。相较仅验证最高分候选，新流程需要对候选逐个计算 bank 得分，验证计算增加，不称为完全等运行时间。
