# v409：同支撑局部精度比较与完整定位验证

## 结论

**获得小幅实际50cm召回提升，尚非广泛精度突破。** 对两份既有v405输出，局部选择器将50cm/5°召回分别从95.43%/95.89%提高到95.66%/96.12%；10cm和25cm召回不变。逐查询审计没有发现这三个门限的成功被破坏。两个结果来自同一个旧候选修复，因此不是两个独立恢复证据，也不是新匹配器或新场景泛化的证明。

最清楚的例子是seq13 frame00131：0.61546m/0.41786° → 0.26919m/0.12997°。接受来自62个共同锚点上的成对特征证据；候选已经存在于旧MNN池。本轮改善的是局部选择，不是生成这个候选。

## 方法实现

新增local_precision_evidence.py，在两个近邻位姿下投影同一批额外验证锚点。只保留两者都在图内、正深度且距原测量不超过4px的交集；相同query token去重。随后分别读取两处coarse/fine RADIO特征，与同一地图描述子比较。候选不能通过各自选择不同锚点获得虚假的更低误差。

每层输出均值、中位数、10%截尾均值、正负差比例、空间格均值以及按样本离散程度标准化的均值，共12个反对称特征。交换base/candidate后特征变号；相同位姿为零。不将这些量称为物理噪声模型或真实似然比，空间相关特征也不构成独立观测。

仅在0.5m/3°局部邻域考虑替换，保留v405的跨模式恢复结果。新规则不直接删除旧保护，而是给局部替换一个单独的比较器。不足6个共同token时拒绝替换；没有通过门限的查询逐位保留原v405位姿。

## 训练与风险边界

mapping seq1/2/4/6训练无截距、L2正则的成对逻辑回归；seq7拟合尺度和接受门限；seq8/11只做确认。训练标签为max(t/0.1m,r/1°)相差至少25%的实际局部候选对，按query平衡权重。没有生成GT附近的人工扰动作为训练候选。

接受门限为0.97025210。seq7规则是：对现有候选代理基线，没有观察到10/25/50cm门限损害，且至少5个不同query产生接受，否则完全拒绝。这是经验标定，不是统计风险上界。

关键限制：mapping池由现有MNN raw/refined候选组成，**没有完整重放mapping上的v357强基线端点**。本轮仍不能宣称真实强基线风险协议已完成。特征先保存为unlabelled文件，再读取mapping误差做标签；训练与标定不读seq10/13真值。

seq7/8/11有效比较对的query加权准确率为93.25%/83.55%/83.33%。仅看refined-refined的可判定对，seq7/8为89.66%/82.35%；seq11只有极少此类对且均未过接受阈值，不能据其准确率宣称可靠泛化。完整端点审计见endpoint_pair_audit.json。

## 仍然存在的问题

- 10cm与25cm没有提高，v408暴露的10cm候选机会尚未广泛兑现；高门限只允许很少局部更新。
- 候选代理分布与真实强基线端点有差距；应优先补足实际强基线mapping运行，以及相同精修阶段之间的困难比较。
- 共同支撑仍依赖全局MNN身份和现有地图代理，交集会丢失部分新可见证据；未学习空间相关性与测量不确定性。
- 塔尖强遮挡的缺失候选问题没有由局部选择修复，跨区域共有支撑、完整三维结构匹配和动态地图成员尚未完成。
- 全部query是持续使用的同场景开发数据，没有新的独立场景确认。

下一步应以真实强基线端点构建局部风险数据，并学习/标定目标尺度的测量误差；不在当前438查询上继续降低接受阈值。v409作为有小幅收益的研究分支保留，不宣称整体问题已解决。
