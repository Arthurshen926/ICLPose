# v408：共享身份、射线负例与粗细外观匹配

## 结论

**本轮没有取得稳定的最终定位召回提升，未替换默认方法。** 已确认粗细RADIO相似度互补可以改善保留路线身份准确率，并在同假设预算下增加10cm正确候选；但共享身份网络泛化不足，现有验证机制无法可靠兑现这些精度机会。只解除局部替换保护反而降低最终召回，不能作为修复上线。

## 实验范围

本轮直接面向当前地面定位任务，不将航空 LoD-Loc 作为主对照或设计约束。完成四个小网络训练（共享/不共享锚点消息 × 原标签/射线补全标签）、两个仅有全局粗细相似度权重的控制模型，以及完整定位、同预算候选合并和局部候选接受消融。所有权重只由 mapping 训练路线拟合；seq7/8/11用于映射路线评估，不用438-query真值训练或选择权重。

## 1. 已实现的结构与监督

新增 SharedIdentityMatcher：相同 prototype ID 的候选引用共享加权 query 消息，经归一化汇聚后回传。编号仅用于等价关系，不进入可学习 embedding。query 侧保留图像/深度邻接；地图侧只使用内在粗细外观，避免将 query 候选集相关统计当作物理锚点属性。与不共享消息、相同参数量的局部控制比较。

overlap头及其标定完全冻结，身份头单独训练；不再由身份梯度更新overlap。已知集合采用集合值身份损失，全候选分布增加权重0.1的原始相似度KL先验。KL是外观先验，不是把unknown标为负例。该实现尚没有完整的地图三维邻接、chart关系或双向结构注意力，不能称为附件结构匹配器已经全部完成。

射线监督补全：在mapping几何代理下，地图锚点投影在图内、距当前query像素超过现有4px模糊带、且query深度有效时，即使该锚点被遮挡，也可排除它是当前像素对应的物理身份。近射线隐藏点和深度缺失项仍保持unknown。重投影规则依赖现有地图几何与渲染监督准确性，没有宣称独立物理真值。

1012个数据对中，只有known数组扩大；特征、positive、target、ids、tokens和邻接逐位不变。没有更改overlap目标。完整逐数组审计保存在 label_completion_audit.json。

新增稀疏候选图互选解码：每个query选身份分数最高的候选，再检查它是否也是该锚点候选引用中的最高分query，继续使用冻结粗相似度下限与均匀求解权重。另有纯coarse相同解码控制；不能将稀疏top16互选视为原全区域MNN严格等价。

## 4. 新候选为何没有直接变成精度提升

|同预算候选池（事后oracle）|10cm %|25cm %|50cm %|
|---|---:|---:|---:|
|control|63.01|93.84|96.80|
|appearance|67.12|93.84|97.03|
|appearance_seed2|68.95|93.84|96.80|

这是逐阈值使用query真值选择候选的诊断上限，不是可实现选择器；真值只在输出冻结后用于解释。10cm候选覆盖增加4.11/5.94个百分点，但25cm没有增加，50cm仅首种子增加0.23个百分点。因此它主要拓展精度机会，并没有解决大范围失败恢复。

precision_selection_diagnostic.json进一步检查：相对原强基线新增的10cm正确机会占全体查询19.86%/21.69%，全部位于原位姿0.5m/3°范围内。原separated_mode保护规则禁止替换这些候选。因此本轮增加local_union消融，只移除该条件，保留其余排名、接受阈值与heldout corroborate要求；它检验局部替换机制，不保证所有oracle机会都能实现。

解除模式隔离后，MNN双种子控制的10cm召回为44.52%，粗细外观两个种子为44.75%/45.21%；相应25cm为88.81%、89.04%/88.81%。它们均未胜过受保护主线。保护规则确实挡住正确候选，但也挡住更多错误替换；这不是可以直接删除的实现bug。新局部比较应接受实际精度风险监督，现有以4px共识为主的验证不能因增加候选就自动具备10cm辨别力。

## 5. 尚未解决的问题与下一步

塔尖frame00142在保留模式隔离的所有新分支中仍未恢复；不能把身份分类小幅改善解释为强遮挡问题已经解决。共享原型消息没有形成有效的新结构匹配器，地图三维相对关系、跨区域共有支撑扩展与可学习地图成员仍未完成。

下一步应把“错误地点恢复”和“同一地点精度改善”分成两个有各自mapping侧风险监督的决策问题。局部精度比较需要与目标尺度相符的测量误差和噪声模型，不能直接套用为分离模式恢复建立的阈值，也不能按本轮query结果继续扫阈值。共享身份网络还需要更强的可迁移关系输入和真正的跨路线困难例，而不是继续增加自由度。

所有新结果来自持续使用的同场景开发查询；两个RANSAC种子不是独立场景验证。当前没有投稿级泛化或显著性证据，也没有RGB→pose端到端资源结果。
