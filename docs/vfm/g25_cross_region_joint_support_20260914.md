# v411：跨检索区域联合求姿、读取范围与求解稳定性

## 结论

本轮获得了真实的最终端点改善，但主要收益来自**联合利用已有区域对应**，不是来自新增地图区域或扩大query读取。检索区域便于找线索，不应同时限定PnP必须独立使用的支撑集合。两个求解种子均改善平均平移误差和25/50cm召回；10cm仍未提升，塔尖frame142仍未解决，完整mapping强端点训练数据也尚未交付。

以下使用全部438个开发查询，顺序固定为seq10、shard0–3，所有输出均为有限位姿。召回同时约束平移/旋转，依次为0.1m/1°、0.25m/2°、0.5m/5°和1m/10°。没有以query真值生成候选或执行接受规则，真值用于推理完成后的评价、案例选择与事后上限诊断。该查询集已被多轮开发查看，不是新封存测试集。

## 2. 修改了什么，为什么这次有效

原分支对四个检索区域分别建立对应并独立产生PnP假设。v411将这四个区域的对应合并，每次最小采样仍选不同query token，允许来自不同区域的约束联合确定同一相机。运行四个固定随机重启，每个最多250个计分假设、1250次尝试；每个query仍只读取原256个求解token。

计分保留物理token唯一性。概念上主计分是：

`S(T) = Σ_i max_{c∈C_i} 1[depth(TX_c)>0 且 ||π(TX_c)-u_ic||≤4px]`。

这里 `u_ic` 是既有细特征读出得到的候选相关像素坐标；同一token的多个地图解释不会重复增加票数。实际实现还使用冻结的次级重投影排序。算法是有限预算鲁棒估计，不保证找到该目标的全局最优。

当身份正确时，不同位置、深度或表面的支撑可以约束单一区域较弱的位姿方向；固定身份下信息矩阵的贡献可相加。但错误对应仍会引入错误解，因此联合求解后保留冻结验证。**不把优化残差降低、投票增加或多次重启一致当作真实精度必然提高的证明。**

现有连续精修原本已经可以在合并库存上选择支撑；本轮关键差别在于更早的初始化阶段也使用跨区域约束。因此，这不是简单增加一次细特征精修。

新增分支相对完整v409增加最多1000个计分PnP假设及其精修/验证成本；已有完整链条成本仍需保留。不能称为与v409同总预算替换。下一节在共同v405 seed1基线上比较相同新增假设上限，回答收益来源。

同一v405 seed1基线的10/25/50cm/1m召回为47.260/89.726/95.434/97.260%，平均平移0.24085m。每条新增分支最多四候选、1000个计分PnP假设，均沿用相同连续精修和额外确认。

这些分支10cm均保持47.260%。最简单的联合旧支撑已经获得主要收益，外观互补邻区没有稳定胜过它。因此尚不应训练展开价值网络并宣称按需新增观测已验证有效。

邻区分支真正联合了旧、新对应，不再要求新区域独自求姿；但其query范围仍为原256个token。两种子仅改变PnP随机性，复用v410已冻结的邻区选择及对应，未重新随机选择邻区。预算上限相同，实际对应规模和运行时间不同，不声称等墙钟成本。

事后诊断中，旧池50cm覆盖96.347%；联合旧支撑seed1使合并候选池达到97.945%，10cm达到67.580%。联合邻区的10cm事后覆盖最高70.776%，但最终10cm没有变化。新假设生成与严格精度接受仍是不同瓶颈，不能将事后上限当作部署结果。

## 4. 扩大query读取：已全量尝试，未达到晋级标准

新增显式实验参数 `--expand-query-bank`：保留原求解token，加入其余MoGe有效token，同时排除冻结验证bank中的所有token。地图检索区域、特征网格分辨率、坐标读出与求解假设上限不变。**这是扩大已有特征的覆盖，不是提高特征分辨率，也不是新RGB提取。**

平均求解token从256增至1656.64，约6.47倍。冻结两参数粗细外观模型，比较原MNN与规范化身份互选。保留同一v405 seed1端点后的结果：

|---|---:|---:|---:|---:|---:|---:|
|扩大读取＋MNN|0.22405 / 0.10778|0.79061 / 0.34728|47.260|89.726|95.434|97.489|
|扩大读取＋规范化互选|0.20839 / 0.10778|0.77632 / 0.34539|47.260|89.726|95.662|97.717|

原始分支与精修后直接输出明显更差，额外确认保住了大部分旧结果；扩大读取未稳定优于联合旧支撑。seq10两臂缓存前端合计约738秒，包含共享载入，不含RGB提取和后续精修；并发执行下不作为严格串行延迟比较。尚未完成“按缺失几何方向只读取必要小区域”的调度。

seed2的frame151从0.2037m恶化至1.3275m；frame134从5.5015m到5.8392m也有连续误差退化。不能只报告净召回，也不能称为逐query无损。

稳定性控制首先将两个求解种子都对同一个v409 control基线执行完整冻结验证，随后要求两者都获准且位姿差不超过现有模式边界0.5m/3°；通过后固定选第一种子，否则保留基线。无GT决策、无新训练、未调小门限。两个重启共享同一对应和验证bank，因此这是求解稳定性检查，**不是独立证据，更不是校准风险上界**。该操作点是观察到开发集重启不稳定后加入的对照，不是事先封存的确认实验。

稳定性门限减少了退化，也拒绝了部分有用更新：25cm回到89.954%，平均平移0.21369m。选择更高召回还是更保守的研究操作点应明确报告，不能拼接两者最佳指标。当前保持研究分支，不更换默认部署端点。

路线内按时间排序、循环块长10、2000次配对bootstrap：seed1平均平移差95%区间约[-0.1181,0]m，seed2约[-0.1141,+0.0014]m。50cm净增区间分别[0,3.425]、[0,1.370]个百分点。改善集中在相关遮挡序列，区间触及零；不能据此宣称已证明广泛统计显著。

## 6. 塔尖与可视化：恢复了邻近粗失败，原始案例仍未解决

联合邻区seed1均匀分支中：frame134约5.50m→0.248m，frame136约7.76m→0.412m。这些是真实最终端点改善，说明不是只修几毫米。但原始frame142仍未通过最终恢复。

frame142在旧＋均匀邻区seed1候选中出现约2.466m/4.992°的解释，比旧17.253m/116.969°更接近；它未通过最终接受，且第二种子未稳定复现。仅联合旧支撑仍未给它带来正确候选；扩大query读取的MNN/身份分支最好有限候选仍约9.43m/37.27°、14.11m/99.96°。不能称为塔尖案例已解决。

`joint_neighbor_v411/support_review.png` 展示上述三张图的旧/新对应及最终预测位姿下的重投影支撑。黄/绿点仅表示正深度且4px内支持，红点为其余对应；它们不是人工确认的真实身份。图像案例根据评价后结果选择，只作说明。

`visibility_review_v411/` 新增原始query与地图特征来源图的并列图，覆盖塔体、低处窗体和右侧屋顶。这些点由GT投影提出，状态文件显式标记未独立核验；不能把投影接近当成真实可见匹配，不能以它们训练或报告人工上限。完整人工对应／候选中人工选择／自动输出的三层诊断仍未完成。

## 7. mapping强端点重放的实际推进与欠账

为连续精修器加入跨路线地图接口和显式query缓存入口。校验真实prototype来源身份、native lineage哈希、地图内容哈希及atlas绑定；拒绝本路线特征、越界身份、混合query路线。不是关闭原有 `mapping/query overlap` 检查。普通query路径保持原检查。

对七条mapping路线现有候选库存的真实来源检查均通过；新增源检查模块覆盖污染、错误路线和越界反例。seq10 v357连续精修实际重放后，names、pose_w2c、usable与历史端点**逐元素完全一致**，见 `strong_endpoint_replay_v411/query_regression_equivalence.json`。

但这些是重放接口和来源协议的有效前置工作：**完整v327→v344→v357 mapping端点尚未生成**，依赖上游对应、连续坐标分支、几何共识和顺序救援的mapping版本。没有把v287普通候选终点冒充v357，没有新训练“真实强端点分布”的精度风险模型。因此附件D仍未交付；10cm候选上限与最终接受之间的空间本轮尚未解决。

## 8. 论文层面可支持与尚不能支持的主张

可以支持：检索单元与求姿支撑不必同边界；固定对应中的跨区域约束在本数据上能够恢复一些粗失败；重复token不会提高计分；优化和接受分离；重启一致性能够提供另一个可观察的保守操作点。

不能支持：该联合PnP机制本身具有顶刊级新颖性；学习地图成员优于固定成员；自动判断缺失几何方向并读取最优互补观测；概率已校准；所有更新无损；跨场景90%召回；塔尖强遮挡已全面解决。

下一步最明确的两项方法任务是：以可见物理身份诊断指导局部读取，避免简单扩大读取；完成mapping完整强端点重放，评估空间块及更新方向上的细特征可分辨性。动态成员与价值学习应建立在已经可验收的闭环上。

## 9. 代码、正确性与复现

- `solve_joint_neighbor_observations.py`：联合旧／新支撑及旧库存独立控制；旧库存模式最终版本不再依赖邻区实验文件。
- `verify_joint_pose_candidates.py`：保留明确指定的基线，执行冻结模式验证与额外token确认。
- `select_stable_joint_pose.py`：验证两输入绑定同一基线、均经过确认，再执行固定种子优先的一致性控制。
- `run_overlap_lod_frontend.py`：显式扩展query读取，默认行为保持不扩展；验证token不得进入求解。
- `refinement_source_contract.py` 与连续精修器接口：真实来源身份检查。

首次旧库存控制的审计 `region_ids` 字段误列邻区ID，但实际 `regions`、采样、坐标和求解使用旧库存。已修正并重新运行两种子候选、精修及最终验证，报告主结果引用 corrected 路径。修正前后位姿数组完全一致；历史产物保留，没有静默改写来源哈希。

全438查询验证了重复拼接旧对应不改变相对验证器特征；验证bank与本轮求解token不相交，新增分支假设上限已审计。源图、query特征仍可能统计相关，计算留出不能写成统计独立。

本轮驱动、日志、源码和产物哈希归档在 `mainline_joint_v411/reproducers/`、`sources/`、`archive_sha256.json`。源码快照是收尾版本；端点元数据记录生成时源码哈希，两者不冒称字节一致。复现命令及历史临时入口保留在归档驱动中，需要新输出目录。167项相关测试通过，六个改动／新增实现模块编译通过，git diff --check通过；日志已归档。
